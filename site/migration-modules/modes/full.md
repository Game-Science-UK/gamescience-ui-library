1. Audit first and build the complete obligation ledger plus render-path inventory
2. Confirm target identity, scope and rollback

4. Migrate foundations and prove **one** vertical slice before broader context work
5. Proceed through low- and medium-risk planned slices without asking for bare continuation
6. Stop only for ambiguous product decisions, destructive actions, unresolved upstream gaps, security/auth changes, unrecoverable validation failures, or genuinely high-risk visual trade-offs
7. Split only materially divergent compositions
8. Preserve application-owned routes where they remain clear
9. Avoid broad route renaming without functional need
10. Classify blocked work as `upstream-gap` with structured proposals — do not quietly retain as migrated
11. Reconcile project state JSON and obligation evidence after every slice
12. Record visual-loss decisions and reference-vs-consumer comparisons
13. Remove redundant forks after validation
14. Preserve application logic
15. Run an independent whole-application coverage audit (coverage-reconstruction)
16. Declare **Full alignment complete** or **Full alignment incomplete** using the ledger

A passing slice must lead automatically into the next planned slice.
“Continue?” must not be required after routine green slices.

Report coverage with dimensions A–E and obligation dispositions — never imply
whole-app coverage from entry surfaces alone.

Full mode is **not** permission for a destructive rewrite.
